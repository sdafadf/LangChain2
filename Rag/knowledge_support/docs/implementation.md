# 实施记录

最新变更：用户指定原 Embedding、原 ChatModel 和 Docker Milvus。当前运行入口使用 `campus_milvus.py`，经 `client_search` 封装调用 Milvus `client.search` 后生成答案；不再使用 SQLite。6 份原资料及 52 个向量片段已完成迁移。以下为初版实施历史。

已批准设计：校园教学诊断与个性化答疑、行政事务与办公整理两个核心场景。

实施顺序：原目录只读检查与备份 → 本地业务模块 → 显式技能协调与可选模型 → 岗位界面 → 异常与安全测试 → 浏览器功能验证与演示录制 → 将已验证文件同步回原项目 → 打包干净参赛源码。

原客服备份保存在独立工作目录，不随参赛包提交。保留旧 Milvus 集合，新应用使用独立 SQLite。原目录历史客服模块保留供回退，但当前入口使用校园模块。参赛包仅采用本次已检查文件。

本地试用优先使用不需外部模型的统计与资料检索，生成接口采用现有 LangChain 依赖；本次不迁移 OpenClaw，也不实现多人账号系统。
