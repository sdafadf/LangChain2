## 当前存储与问答流程

## 原 ChatModel 接入

运行模式默认选择“原项目 ChatModel”，沿用原客服的 `CHAT_PROVIDER` / `CHAT_MODEL`，缺省值分别为 `deepseek` / `deepseek-v4-flash`。DeepSeek 使用 `DEEPSEEK_BASE_URL`、`DEEPSEEK_API_KEY`；OpenAI 使用相应 `OPENAI_*` 配置。读取本目录与最近上级 `.env`，进程环境变量优先。不把 embedding 密钥混用于 DeepSeek，不将密钥写入代码或导出。

学习答疑、行政流程回答、课堂练习与课程改进、办公文稿整理均使用所选 ChatModel。页面启动不调用模型；用户提交任务后才发送必要文本。使用远程 ChatModel 时相关资料、问题和必要历史会发往配置服务。失败不会自动换模型。“离线工具”仅关闭回答生成，知识检索仍需 Milvus 与 Embedding 服务；学情统计可独立运行。

## Embedding 接入更新

知识检索默认使用原项目 embedding：从项目本目录及最近上级 `.env` 读取 `EMBED_MODEL_NAME`、`OPENAI_BASE_URL`、`OPENAI_API_KEY`（进程环境变量优先）。未设置模型名时使用 `text-embedding-3-large`。不会复制密钥到源码或提交包。

上传点击“生成向量并写入 Milvus”时调用原 embedding 服务；提问使用同一配置生成查询向量，调用 `client.search` 按 COSINE 相似度检索。按模型和接口地址过滤资料，维度不一致时拒绝查询。相似度下限 0.25 是启发式筛选，需用真实课程资料评估，不等同于正确率。

每份资料的全部片段成功写入后才写入完成标记；检索只匹配已完成资料。上传中断可能留下未提交片段，但不会被检索，重试使用稳定 ID 继续写入。建索引和查询均会把相应文本发送到原项目配置的 embedding 服务。

“运行模式”控制回答生成，检索固定使用 Docker Milvus。首次离线演示视频拍摄于 embedding 与 Milvus 接入前，仅展示当时的基础流程；当前实现以本说明和代码为准。

## 数据与安全

- CSV 仅允许“学生编号,知识点,得分,满分”四列。学生编号为 S001 形式；满分须为正数，得分不得越界。相同学生和知识点的重复记录需明确勾选保留全部才可导入。
- 统计按“得分之和 / 满分之和”加权；关注阈值可调，不代表真实掌握概率或诊断结论。
- 上传片段与向量存于 Docker Milvus 校园集合；同分类相同内容与模型配置去重。保留原客服集合不变；本版不提供用户账户和跨岗位权限控制。
- 成绩原始行不写入磁盘，页面状态和问答历史属于当前 Streamlit 会话，服务重启会丢失。知识资料持久保存。删除资料会清除当前会话相关问答；其他已有浏览器会话可能仍含旧原文，需关闭。
- 导出学情只包含知识点汇总；Markdown 预览会遮盖常见电话、邮箱、证件号，姓名与学校标识需人工复核。CSV 输出防范公式注入。
- 本机文件未做应用层加密；使用操作系统账户和设备权限保护数据。本版不要直接向多人网络开放。
- TXT 为 UTF-8；PDF 须含可提取文字；Word 支持正文表格。单文件最多 10 MB、20 万字符，扫描 PDF 先 OCR。Milvus 相似度不是答案正确率。
- 默认关闭 Streamlit 遥测及 LangChain 跟踪。密钥不显示到错误信息，不保存到源码或导出文件。

## 代码结构

- `app.py`：岗位工作台、配置、预览、下载和异常提示。
- `campus_core.py`：输入验证、统计、规则整理、脱敏与安全导出；旧 SQLite 类仅供历史回归测试，运行入口不使用。
- `campus_engine.py`：显式技能协调、检索到生成的数据流、LangChain 模型接口与网络边界。
- `campus_embeddings.py`：原项目 embedding 配置和向量服务调用；旧 SQLite 类仅保留作历史实现参考，不由运行入口调用。
- `campus_milvus.py`：Docker Milvus 连接、校园集合初始化、片段提交、去重、删除与 `client_search`。
- `migrate_to_milvus.py`：一次性读取旧文件、复用向量迁移到 Milvus；不是运行时依赖。
- `ingestion.py`：沿用原项目文档解析器；校园界面只调用 `load_document`，不调用其 Milvus 入库逻辑。
- `skills/*/SKILL.md`：技能输入、输出、边界和验收说明。
- `test_campus.py` / `verify.py`：离线业务与界面验证。
- `docs/`：设计、评分指标、部署和演示说明。

技能协作采用显式流程编排：学情计算结果传入教学建议，资料检索结果传入问答生成。不是多个自主 Agent 并行执行；原客服 Agent 源码保留在原目录，但新入口不默认调用。

## 验证

```text
python verify.py
```

覆盖加权计算、异常成绩、重复记录、知识分类隔离、去重删除、无依据回答、离线不调用模型、本地地址约束、模型失败、导出防护和完整界面流程。测试使用合成数据与模拟模型；真实模型联调结果以 `docs/validation.md` 为准。

## 参赛材料

源码与一键启动教程包含于本目录。`docs/demo-script.md` 为录制脚本；功能演示视频放在 `output/playwright/`。文字与 PPT 官方模板尚未提供，应收到后再适配。提交前不要包含 `.env`、真实资料库、真实问答、旧客服截图或旧学校资料。用单独的干净参赛包提交，避免直接压缩含历史文件的原目录。
